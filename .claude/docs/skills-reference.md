# 可用技能（斜杠命令）

| 命令 | 用途 |
|------|------|
| `/start` | 首次入门 — 询问你的当前进度，然后引导至正确的工作流 |
| `/design-review` | 审查游戏设计文档的完整性和一致性 |
| `/code-review` | 针对文件或变更集（Changeset）的架构级代码审查 |
| `/playtest-report` | 生成结构化的试玩报告模板 |
| `/balance-check` | 分析游戏平衡数据并标记异常值 |
| `/sprint-plan` | 生成或更新 Sprint 计划 |
| `/bug-report` | 创建结构化的缺陷报告 |
| `/architecture-decision` | 创建架构决策记录（ADR, Architecture Decision Record） |
| `/asset-audit` | 审计资产的命名、尺寸和管线合规性 |
| `/milestone-review` | 审查里程碑进度并生成状态报告 |
| `/onboard` | 为新贡献者或代理生成入职上下文 |
| `/prototype` | 搭建可丢弃的原型以验证机制或技术方案 |
| `/release-checklist` | 生成并验证当前构建的发布前清单 |
| `/changelog` | 从 Git 提交记录和 Sprint 数据自动生成变更日志 |
| `/retrospective` | 运行结构化的 Sprint 或里程碑回顾 |
| `/estimate` | 生成结构化的工作量估算，包含复杂度和风险分析 |
| `/hotfix` | 紧急修复工作流，带审计跟踪，绕过正常 Sprint 流程 |
| `/tech-debt` | 扫描、跟踪、优先级排序并报告整个代码库的技术债务（Tech Debt） |
| `/scope-check` | 将功能或 Sprint 范围与原计划进行对比分析，标记范围蔓延（Scope Creep） |
| `/localize` | 本地化（Localization）工作流：扫描硬编码字符串、提取、验证翻译 |
| `/perf-profile` | 结构化性能分析，识别瓶颈并生成优化建议 |
| `/project-stage-detect` | 自动分析项目状态、检测开发阶段、识别缺失项并推荐后续步骤 |
| `/reverse-document` | 从现有实现逆向生成设计或架构文档（从代码反向推导） |
| `/team-combat` | 编排战斗团队：game-designer + gameplay-programmer + ai-programmer + technical-artist + sound-designer + qa-tester |
| `/team-narrative` | 编排叙事团队：narrative-director + writer + world-builder + level-designer |
| `/team-ui` | 编排 UI 团队：ux-designer + ui-programmer + art-director |
| `/team-release` | 编排发布团队：release-manager + qa-lead + devops-engineer + producer |
| `/team-polish` | 编排打磨团队：performance-analyst + technical-artist + sound-designer + qa-tester |
| `/team-audio` | 编排音频团队：audio-director + sound-designer + technical-artist + gameplay-programmer |
| `/team-level` | 编排关卡团队：level-designer + narrative-director + world-builder + art-director + systems-designer + qa-tester |
| `/launch-checklist` | 跨所有部门的完整上线就绪验证 |
| `/patch-notes` | 从 Git 历史和内部数据生成面向玩家的补丁说明 |
| `/brainstorm` | 使用专业工作室方法（MDA、SDT、Bartle、动词优先）进行引导式创意构思 |
| `/gate-check` | 验证开发阶段之间推进的就绪状态（通过/有疑虑/不通过） |
| `/map-systems` | 将游戏概念拆解为系统，映射依赖关系，确定设计优先级，指导逐系统 GDD 编写 |
| `/design-system` | 针对单个游戏系统进行引导式、逐节的 GDD 编写，支持交叉引用和增量写作 |
| `/setup-engine` | 配置引擎和版本，检测知识缺口，填充版本感知的参考文档 |
