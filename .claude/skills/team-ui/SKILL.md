当此技能被调用时，通过结构化管线编排 UI 团队。

**决策点：** 在每个阶段转换时，使用 `AskUserQuestion` 将子代理的方案作为可选项呈现给用户。在对话中展示代理的完整分析，然后用简洁的标签记录决策。用户必须批准后方可进入下一阶段。

## 团队组成
- **ux-designer** — 用户流程、线框图、无障碍访问、输入处理
- **ui-programmer** — UI 框架、屏幕、控件、数据绑定、实现
- **art-director** — 视觉风格、布局打磨、与美术圣经的一致性

## 如何委派

使用 Task 工具将每位团队成员作为子代理启动：
- `subagent_type: ux-designer` — 用户流程、线框图、无障碍访问、输入处理
- `subagent_type: ui-programmer` — UI 框架、屏幕、控件、数据绑定
- `subagent_type: art-director` — 视觉风格、布局打磨、美术圣经一致性

始终在每个代理的提示中提供完整上下文（功能需求、现有 UI 模式、平台目标）。在管线允许的地方并行启动独立代理（例如，第 4 阶段的审查代理可同时运行）。

## 管线

### 第 1 阶段：UX 设计
委派给 **ux-designer**：
- 定义此功能的用户流程（入口点、状态、出口点）
- 为每个屏幕/状态创建线框图
- 规定交互模式：键盘/鼠标和游戏手柄如何导航此界面？
- 定义无障碍要求：文字大小、对比度、色盲安全
- 识别 UI 需要展示的数据（读取哪些游戏状态？）
- 输出：包含线框图和交互映射的 UX 规格

### 第 2 阶段：视觉设计
委派给 **art-director**：
- 对照美术圣经审查线框图
- 定义视觉处理方案：颜色、字体、间距、动画
- 规定资产需求（图标、背景、装饰元素）
- 确保与现有 UI 屏幕的一致性
- 输出：包含样式说明的视觉设计规格

### 第 3 阶段：实现
委派给 **ui-programmer**：
- 按照 UX 规格和视觉设计实现 UI
- 确保 UI 绝不拥有或修改游戏状态——仅展示，通过事件请求操作
- 所有文本通过本地化系统——禁止硬编码字符串
- 同时支持两种输入方式（键盘/鼠标 + 游戏手柄）
- 实现无障碍功能（文字缩放、色盲模式支持）
- 连接数据绑定到游戏状态
- 输出：已实现的 UI 功能

### 第 4 阶段：审查（并行）
并行委派：
- **ux-designer**：验证实现是否符合线框图和交互规格。测试纯键盘和纯手柄导航。检查无障碍访问。
- **art-director**：验证与美术圣经的视觉一致性。在最低和最高支持分辨率下进行检查。

### 第 5 阶段：打磨
- 处理审查反馈
- 验证动画可跳过并尊重运动偏好设置
- 确认 UI 音效通过音频事件系统触发
- 在所有支持的分辨率和宽高比下进行测试

## 输出
一份总结报告，涵盖：UX 规格状态、视觉设计状态、实现状态、无障碍合规性、输入方式支持情况，以及任何未解决的问题。
