# 角色攻击防御系统需求

> **状态**：动画动作原型已实现，碰撞与伤害阶段待设计
> **创建日期**：2026-07-22
> **当前阶段**：玩家角色动画动作原型；AI、碰撞、伤害和真实命中来源后续接入
> **技术设计**：[角色攻击防御系统技术设计](../design/sekiro-attack-defense-system.md)

## 一、背景

项目已经具备以下战斗基础：

- `AnimAssets.lua` 已登记轻攻击、左右重攻击、地面连段、空中攻击、防御移动、格挡反馈和多组弹反动画。
- `SKInputManager` 已采集攻击按下、攻击长按时长、防御保持和动作输入缓冲。
- `ASKWeapon` 已具备攻击碰撞开关和单次攻击命中去重能力，但当前动画动作阶段不接入该能力。
- `ABP_Sekiro.lua` 已支持 Root Motion、移动状态机和上半身武器 Slot。

当前已经接入统一的战斗动作状态机、左右刀侧管理、轻重攻击分流，以及防御键驱动的弹反动画闭环。项目尚未实现可稳定发起攻击的 AI，也暂不接入碰撞和伤害，因此本阶段使用可控的“模拟来袭上下文”代替真实命中来源，先验证玩家攻击、防御和弹反动画行为。

## 二、目标

1. 使用已有动画资产完成地面/空中/落地轻攻击、重攻击、防御和弹反的动画动作闭环。
2. 轻攻击按照 `Right -> Left -> Combo_01 -> Combo_02 -> Combo_03` 固定动作链推进；续段只能在当前动画的 `CanAcceptLightAttack` 窗口内登记。
3. 重攻击由攻击键长按触发，当前攻击侧在动画的不可打断区间保持不变；动画结束后不保留额外宽限。
4. 当前攻击侧与下一攻击侧分离；`AttackSide` 只在 `CanCancelToGuard` 已开放的恢复阶段提交下一侧，不覆盖本动作的当前攻击侧。
5. 弹反只能由“有效来袭期间的新防御按下边沿”触发；没有来袭时按防御只进入普通防御。
6. 不同来袭攻击类型通过配置选择不同的弹反 Type，连续弹反阶段选择对应 Stage 动画。
7. C++ 只提供通用动作宿主、动画采样、输入事件和来袭上下文接口，Lua 负责具体动作编排与弹反动画选择。
8. Falling 状态从 `Air_Combo_01` 开始空中三连；活动空中攻击落地时立即进入同编号 `Land_Combo`，不影响没有攻击的普通 Jump Land。
9. 跳跃输入必须经过战斗状态仲裁：地面攻击只在 `CanCancelToJump` 窗口内允许，普通防御可以直接取消并在持续按住时转入空中防御。

## 三、范围

### 3.1 本期范围

- 地面轻攻击五段链。
- 空中轻攻击三段链，以及活动空中攻击落地时的同编号落地攻击。
- 落地轻攻击三段链。
- 左右重攻击及重攻击连续衔接。
- 重攻击转回轻攻击链。
- 动画曲线驱动的攻击侧提交、轻重攻击输入窗口和普通防御取消窗口。
- 攻击输入的短按、长按和窗口内有效性判定。
- 主动防御、持续防御和防御释放动画。
- 攻击首尾跳跃取消窗口，以及地面防御跳跃后的空中 Raise/Idle/Lower。
- 有效来袭期间由防御键新按下触发的弹反动画。
- 来袭攻击类型到 `AnimAssets.Deflect.Type_*_Stage_*` 的可配置映射。
- 无 AI、无碰撞条件下可由 PIE/AIBridge 调用的模拟来袭测试接口。
- 动画自然结束、弹反或主动取消导致的动作中断与状态清理。

### 3.1.1 当前动画原型规则优先级

本节是当前可执行验收基线。战斗曲线来自原始 TAE 帧区间，并直接写入活动 `UAnimSequence`。

- 普通防御只在 `CanCancelToGuard=1` 时打断攻击；曲线为零的中段必须保持当前攻击侧且完整播放。
- 弹反仍由防御键触发，并且只有成功消费有效来袭上下文时才可以无视上述普通防御打断限制。
- 下一段攻击只能在动画内的 `CanAcceptLightAttack` 或 `CanAcceptHeavyAttack` 窗口触发；轻重判定完成后立即混合到下一动作，不等待当前动画的恢复段结束。
- 动画结束后没有连段或刀侧宽限；无已登记续段时立即清空连段并恢复默认右侧。
- `AttackSide` 只更新下一攻击侧，当前攻击的 `CommittedAttackSide` 在整段动作中不被曲线修改。
- Guard 和当前阶段 Deflect 的刀侧统一为左侧；Guard Lower 完整结束或 Deflect 退出后恢复默认右侧。
- 空中和落地连段的长按输入统一按轻攻击处理，不能切换到重攻击；第三段为终结段。
- 空中/落地动作首版不写 `AttackSide`，沿用动作开始时刀侧；后续视觉核验后再补充侧向曲线。
- Ground/Land 攻击只有 `CanCancelToJump=1` 时允许起跳；Air 攻击和其他战斗状态禁用跳跃。
- `GuardRaise/Guarding/GuardLower` 可直接取消到 Jump；防御键持续按住时，Jump 后依次使用 `Air_Raise -> Air_Idle`，释放时使用 `Air_Lower`。

### 3.2 后续范围

- AI 攻击请求和真实攻击者。
- 武器碰撞、连续刀刃 Sweep 和真实命中事件。

- 危字攻击、识破、踩踏和投技。

- 战技、义手忍具和道具取消链。
- 网络同步。

## 四、术语

| 术语 | 定义 |
| --- | --- |
| 轻攻击 | 攻击键在长按阈值前释放，或当前动作不允许重攻击时产生的普通攻击意图。 |
| 重攻击 | 攻击键持续按住达到配置阈值后产生的攻击意图。 |
| 当前攻击侧 | 当前正在执行并用于命中、格挡和弹反方向判断的 Left/Right；一段攻击期间保持不变。 |
| 下一攻击侧 | 当前动画通过 `AttackSide` 曲线提交、供下一段攻击选择使用的 Left/Right。 |
| 连段窗口 | 动画允许接收下一次轻攻击的时间区间。 |
| 重攻击窗口 | 动画允许接收长按重攻击的时间区间。 |
| 取消窗口 | 当前攻击允许主动转入防御或闪避的时间区间。 |
| 有效输入 | 按下起点位于对应动画窗口内，尚未消费、未过期且未被更高优先级动作清除的输入。 |
| 动作序列号 | 每次开始攻击时生成的唯一运行时编号，用于拒绝已经中断动作的迟到曲线和输入。 |
| 模拟来袭上下文 | 测试接口创建的一段有限有效期，表示玩家当前正受到某种类型攻击；本阶段不依赖攻击者、碰撞或伤害。 |
| 来袭攻击类型 | 用于选择弹反动画 Type 的稳定语义，例如 Light、Heavy、Thrust、Special；不等同于动画资产编号。 |
| 弹反输入 | 发生时间位于有效来袭上下文内的防御键 Started 边沿；持续按住、防御释放或无来袭时的按下均不算弹反输入。 |

## 五、动画资产基线

| 玩法语义 | 动画资产 |
| --- | --- |
| 第一段右侧轻攻击 | `AnimAssets.Attack.Right` |
| 第二段左侧轻攻击 | `AnimAssets.Attack.Left` |
| 后续轻攻击 | `AnimAssets.Attack.Combo_01`、`Combo_02`、`Combo_03` |
| 空中轻攻击 | `AnimAssets.Attack.Air_Combo_01`、`Air_Combo_02`、`Air_Combo_03` |
| 落地轻攻击 | `AnimAssets.Attack.Land_Combo_01`、`Land_Combo_02`、`Land_Combo_03` |
| 右侧重攻击 | `AnimAssets.Attack.Charged_Thrust_Right` |
| 左侧重攻击 | `AnimAssets.Attack.Charged_Thrust_Left` |
| 防御起手/循环/结束 | `AnimAssets.Guard.Raise`、`Idle`、`Move_*`、`Lower` |
| 轻格挡反馈 | `AnimAssets.Guard.Shake` |
| 中/重格挡反馈 | `AnimAssets.Guard.Interrupted`、`Interrupted_Heavy` |
| 弹反反馈 | `AnimAssets.Deflect.Type_*_Stage_*`；Type 由来袭攻击类型映射，Stage 由连续弹反阶段选择。 |

`Combo_01~03` 的实际挥刀侧必须通过动画检查确认，并写入对应动画的 `AttackSide` 曲线。不得仅根据资产名称推测其左右侧。

## 六、轻攻击需求

### 6.1 固定连段

轻攻击动作链固定为：

```text
Right -> Left -> Combo_01 -> Combo_02 -> Combo_03 -> End
```

### 6.2 续段规则

- **REQ-ATK-001**：一次全新的轻攻击链必须从 `Right` 开始。
- **REQ-ATK-002**：只有 `CanAcceptLightAttack > 0` 时产生的有效轻攻击输入才能推进下一段。
- **REQ-ATK-003**：一个窗口最多消费一个轻攻击输入，多次按键不得跳过中间攻击。
- **REQ-ATK-004**：续段输入只能推进一段，进入新动作后必须重新等待该动作自己的窗口。
- **REQ-ATK-005**：窗口关闭且没有有效续段输入时，当前动画允许自然收招，本轮连段结束。
- **REQ-ATK-006**：连段结束后的下一次轻攻击重新从 `Right` 开始，不从上次中断位置恢复。
- **REQ-ATK-007**：`Combo_03` 不允许继续轻攻击，播放完成后强制结束连段。

### 6.3 空中与落地攻击

- **REQ-AIR-001**：Neutral 且 CharacterMovement 处于 Falling 时，攻击输入必须从 `Air_Combo_01` 开始。
- **REQ-AIR-002**：空中链固定为 `Air_Combo_01 -> Air_Combo_02 -> Air_Combo_03 -> End`，只在 `CanAcceptLightAttack` 窗口内续段。
- **REQ-AIR-003**：活动 `Air_Combo_01~03` 检测到落地时，必须立即切换到同编号 `Land_Combo_01~03`。
- **REQ-AIR-004**：没有活动空中攻击时，落地不得启动战斗 Montage，继续使用原有 Jump Land。
- **REQ-AIR-005**：落地链固定为 `Land_Combo_01 -> Land_Combo_02 -> Land_Combo_03 -> End`。
- **REQ-AIR-006**：空中和落地动作均不允许重攻击；长按只要在轻攻击窗口内开始，仍解析为下一段轻攻击。
- **REQ-AIR-007**：落地转换必须清除尚未释放的空中攻击候选，避免旧输入跨动作执行。

## 七、重攻击需求

### 7.1 输入识别

- **REQ-HVY-001**：重攻击与轻攻击共用攻击键。
- **REQ-HVY-002**：攻击键按住达到 `HeavyHoldThreshold` 后才生成重攻击意图，默认阈值为 `0.30s`。
- **REQ-HVY-003**：攻击按下起点必须位于 `CanAcceptHeavyAttack > 0` 的窗口内，才有资格升级为重攻击。
- **REQ-HVY-004**：在达到阈值前释放时，若按下起点同时位于轻攻击窗口，则生成轻攻击意图。
- **REQ-HVY-005**：同一按键候选一旦升级为重攻击，必须覆盖尚未执行的轻攻击候选。

### 7.2 可用动作

- **REQ-HVY-006**：`Right`、`Left`、`Charged_Thrust_Right` 和 `Charged_Thrust_Left` 均允许配置重攻击窗口。
- **REQ-HVY-007**：`Combo_01~03` 不允许转入重攻击；其 `CanAcceptHeavyAttack` 必须为零。
- **REQ-HVY-008**：在不允许重攻击的 Combo 动作中，攻击键长按不得阻塞合法的轻攻击续段。
- **REQ-HVY-009**：Neutral 状态直接长按攻击时，首个重攻击侧由 `InitialHeavySide` 配置，默认使用 Right。

### 7.3 左右侧衔接

重攻击和轻攻击共享下一攻击侧。默认衔接如下：

| 当前攻击 | 下一攻击侧 | 轻攻击输入 | 重攻击输入 |
| --- | --- | --- | --- |
| `Right` | Left | `Left` | `Charged_Thrust_Left` |
| `Left` | Right | `Combo_01` | `Charged_Thrust_Right` |
| `Charged_Thrust_Right` | Left | `Left` | `Charged_Thrust_Left` |
| `Charged_Thrust_Left` | Right | `Combo_01` | `Charged_Thrust_Right` |

- **REQ-HVY-010**：连续重攻击必须按动画曲线提交的左右侧交替选择资源。
- **REQ-HVY-011**：重攻击后的轻攻击必须根据下一攻击侧返回轻攻击链，而不是无条件从 `Right` 重启。
- **REQ-HVY-012**：没有有效后续输入时，重攻击自然结束并终止当前攻击链。

## 八、攻击侧曲线需求

### 8.1 曲线语义

`AttackSide` 使用整数语义和阶梯插值：

| 值 | 语义 |
| --- | --- |
| `-1` | 下一攻击侧提交为 Left。 |
| `0` | 保持当前值，不提交切换。 |
| `1` | 下一攻击侧提交为 Right。 |

- **REQ-SIDE-001**：`AttackSide` 表达下一攻击侧，不得直接覆盖当前攻击侧。
- **REQ-SIDE-002**：当前攻击侧在动作开始时提交，在该动作全部攻击盒关闭前保持不变。
- **REQ-SIDE-003**：`AttackSide` 非零区间必须位于当前动作最后一个攻击盒关闭之后。
- **REQ-SIDE-004**：`AttackSide` 必须不晚于对应轻攻击或重攻击输入窗口开始帧提交。
- **REQ-SIDE-005**：有效输入产生时必须快照下一攻击侧；后续曲线变化不得修改已经接受的输入候选。
- **REQ-SIDE-006**：动画混合产生的中间值不得触发侧向切换；运行时必须使用阈值和每动作一次性消费保护。
- **REQ-SIDE-007**：当前动作被中断后，不得继续消费该动作剩余的 `AttackSide` 曲线。

### 8.2 标准时间顺序

```text
动作启动
-> 当前侧攻击盒开启
-> 命中阶段
-> 当前侧攻击盒关闭
-> AttackSide 提交下一侧
-> 轻/重攻击输入窗口
-> 收招或进入下一动作
```

## 九、窗口和输入需求

### 9.1 必需曲线

| 曲线 | 类型 | 作用 |
| --- | --- | --- |
| `AttackHitbox` | int enum | 后续碰撞阶段使用；当前阶段只登记和审计，不作为动画动作前置条件。 |
| `AttackSide` | int enum | 提交下一攻击侧。 |
| `CanAcceptLightAttack` | int bool | 接受轻攻击续段。 |
| `CanAcceptHeavyAttack` | int bool | 接受长按重攻击。 |
| `CanCancelToGuard` | int bool | 允许攻击方主动切入防御。 |
| `CanCancelToJump` | int bool | 允许地面攻击取消到物理跳跃。 |
| `CanCancelToDodge` | int bool | 允许攻击方主动切入闪避。 |

- **REQ-WIN-001**：各窗口必须由动画曲线提供，不得使用统一的 `0.5s` 连段超时替代。
- **REQ-WIN-002**：输入按下起点在窗口外时无效，即使长按阈值在窗口内达到也不得触发。
- **REQ-WIN-003**：窗口内开始的长按候选可以在窗口关闭后完成轻重分类，但不得晚于当前动作结束。
- **REQ-WIN-004**：窗口关闭后产生的新输入不得补入已经关闭的窗口。
- **REQ-WIN-005**：动作被中断时必须清除该动作接受的所有未执行候选。

## 十、防御与弹反需求

### 10.1 主动防御

- **REQ-DEF-001**：Neutral 状态按下防御必须立即建立机械防御状态，并播放 `Guard.Raise`。
- **REQ-DEF-002**：持续按住防御进入 `Guard.Idle` 或四向 `Guard.Move_*`。
- **REQ-DEF-003**：释放防御播放 `Guard.Lower`，结束机械防御状态。
- **REQ-DEF-004**：攻击方主动从轻攻击或重攻击切入防御时，必须满足当前动画的 `CanCancelToGuard`。
- **REQ-DEF-005**：普通防御的 Raise、Guarding 和 Lower 阶段都允许 Jump；执行顺序必须为清理地面防御、请求物理 Jump、按 Held 状态决定是否进入空中防御。
- **REQ-DEF-006**：防御键在 Jump 后仍按住时播放 `Guard.Air_Raise`，随后使用 `Guard.Air_Idle`；空中释放时播放 `Guard.Air_Lower`。
- **REQ-DEF-007**：防御键在起跳后已经释放时不得自动进入空中防御。

### 10.2 跳跃取消

- **REQ-JUMP-001**：Neutral 状态保持原有 Jump 行为。
- **REQ-JUMP-002**：Ground/Land 轻重攻击只在输入事件时间采样到 `CanCancelToJump >= 0.5` 时允许 Jump。
- **REQ-JUMP-003**：合法 Jump 必须停止当前 Montage、使旧 ActionSerial 失效并清理连段候选。
- **REQ-JUMP-004**：攻击中段、Air 攻击、PendingAttack、Deflect 和 Dodge 状态必须吞掉 Jump Started。
- **REQ-JUMP-005**：原始 JT119 缺少首段窗口的 `Left`、`Combo_01` 和 Land 动作统一补前 `0.10s` 跳跃取消窗口。

### 10.2 当前阶段弹反触发

```text
模拟来袭开始(AttackType, ContextSerial, ActiveStart, ActiveEnd)
-> 玩家在有效时间区间内新按下 Guard
-> 消费本次来袭上下文
-> 根据 AttackType 选择 Deflect Type
-> 根据连续弹反阶段选择 Stage
-> CombatFullBodySlot 播放弹反动画
-> 动画结束后按 Guard 是否仍按住返回 Guarding 或 Neutral
```

- **REQ-DEF-005**：只有防御键 `Started` 的事件时间位于有效来袭上下文内时才能触发 Deflect。
- **REQ-DEF-006**：没有有效来袭上下文时按下防御，只播放 `Guard.Raise` 并进入普通防御，不得播放弹反动画。
- **REQ-DEF-007**：来袭开始前已经持续按住防御时，来袭出现不得自动触发 Deflect；必须释放并重新按下形成新的 Started 边沿。
- **REQ-DEF-008**：同一 `ContextSerial` 最多触发一次 Deflect，成功触发后立即消费，迟到输入不得重复播放。
- **REQ-DEF-009**：来袭攻击类型必须通过 Lua 配置映射到不同的 Deflect Type；不得在 C++ 中硬编码具体 `Type_XX_Stage_XX` 资产名。
- **REQ-DEF-010**：Type 01～03 的 Stage 01～03 表示同一类型内的连续弹反阶段；连续窗口超时、普通防御或其他动作中断后重置到 Stage 01。
- **REQ-DEF-011**：Type 04 当前只有 Stage 01，后续连续弹反仍保持 Stage 01，不得构造不存在的资产路径。
- **REQ-DEF-012**：弹反动画播放期间再次收到旧来袭或旧防御回调时，必须通过动作序列号和上下文序列号拒绝。
- **REQ-DEF-013**：本阶段提供测试接口创建和清除模拟来袭上下文；测试接口只提供动画触发条件，不生成攻击者、碰撞、伤害或 AI 行为。
- **REQ-DEF-014**：弹反动画结束时若 Guard 仍按住则进入 `Guarding`，否则回到 `Neutral`；释放事件不得中途把弹反动画替换成 `Guard.Lower`。

### 10.3 后续真实命中裁决

无敌、方向、Block、伤害、攻击方中断和架势结果延后到碰撞与伤害阶段。真实命中接入后只负责创建与测试接口相同的数据上下文，不得绕过本阶段已经验证的防御输入和动画选择流程。

## 十一、HP 与架势需求（后续阶段）

- **REQ-VIT-001**：普通命中造成 HP 伤害和目标架势伤害。
- **REQ-VIT-002**：格挡默认不造成 HP 伤害，但增加防御方架势。
- **REQ-VIT-003**：弹反默认不造成防御方 HP 伤害，并增加攻击方架势。
- **REQ-VIT-004**：架势达到上限时进入 PostureBroken，优先级高于普通动作。
- **REQ-VIT-005**：架势只在未受击、未防御并经过恢复延迟后恢复。
- **REQ-VIT-006**：所有伤害、架势和恢复参数必须来自配置，不得在武器 Actor 中硬编码。

## 十二、优先级与中断

动作优先级从高到低为：

```text
弹反动画
> 主动防御
> 闪避
> 重攻击续段
> 轻攻击续段
> 自然收招
```

- **REQ-INT-001**：有效弹反输入可以中断 Neutral、GuardRaise、Guarding 和允许防御取消的攻击动作。
- **REQ-INT-002**：弹反动画播放期间不接受普通攻击续段、重复 Guard Started 或 Guard Lower 动画替换。
- **REQ-INT-003**：主动 Guard/Dodge 取消必须服从对应动画曲线。
- **REQ-INT-004**：任何攻击动画中断都必须清理输入候选并停止消费旧动作曲线；攻击盒清理由后续碰撞阶段补充。
- **REQ-INT-005**：中断后本轮轻攻击链结束；下一次全新轻攻击从 `Right` 开始。

## 十三、边界情况

| 场景 | 预期结果 |
| --- | --- |
| 同一窗口多次按攻击 | 合并为一次续段，不跳段。 |
| 轻攻击候选随后达到长按阈值 | 当前节点允许重攻击时升级为 Heavy，否则保持 Light。 |
| 窗口内按下、窗口外释放 | 使用按下时快照继续分类，动作结束前有效。 |
| 曲线混合值为 `0.5` | 不提交侧向，等待稳定达到阈值。 |
| 动作切换后收到旧输入回调 | 通过动作序列号拒绝。 |
| 无来袭时按下 Guard | 播放普通 Guard Raise，不触发 Deflect。 |
| 已按住 Guard 后才创建来袭 | 不自动弹反；必须重新按下 Guard。 |
| Guard Started 与来袭边界同帧发生 | 按事件时间是否落在 `[ActiveStart, ActiveEnd]` 内裁决，不依赖回调先后。 |
| 同一来袭窗口连续收到 Guard 回调 | `ContextSerial` 只消费一次，只播放一次 Deflect。 |
| 弹反动画期间释放 Guard | 记录释放状态但不打断弹反；动画结束后回 Neutral。 |
| Deflect 与攻击续段同帧发生 | Deflect 优先，续段作废。 |
| 重攻击连续输入终止 | 当前重攻击收招，攻击链结束。 |
| Combo 中长按攻击 | 不产生重攻击，可按轻攻击窗口继续 Combo。 |

## 十四、非功能需求

- **REQ-NFR-001**：战斗判定在游戏线程执行，不得在动画工作线程修改 Actor、组件或 Lua 状态。
- **REQ-NFR-002**：同一模拟来袭 `ContextSerial` 最多触发一次弹反动画。
- **REQ-NFR-003**：攻击窗口在 30fps 和 60fps 下必须产生一致结果。
- **REQ-NFR-004**：动画淡入淡出不得造成旧动作曲线被新动作重复消费。
- **REQ-NFR-005**：C++ 不硬编码 `/Game` 动画路径、具体连段名称或角色专属数值。
- **REQ-NFR-006**：所有状态转换应提供可开关的调试日志，日志至少包含动作 ID、序列号、当前侧、下一侧、输入类型和中断原因。

## 十五、验收标准

### 15.1 轻攻击

- [ ] 连续在各自动画窗口内短按攻击，正确播放 `Right -> Left -> Combo_01 -> Combo_02 -> Combo_03`。
- [ ] 任意一段没有有效续段输入时自然结束，下一次攻击从 `Right` 开始。
- [ ] 同一窗口连按不会跳过攻击段。
- [ ] Combo 阶段长按不会触发重攻击，也不会阻塞合法轻攻击续段。

### 15.2 重攻击与侧向

- [ ] `Right` 的有效重攻击输入进入 `Charged_Thrust_Left`。
- [ ] `Left` 的有效重攻击输入进入 `Charged_Thrust_Right`。
- [ ] 连续重攻击按 `Right/Left` 交替播放。
- [ ] 重攻击窗口内短按可按当前下一攻击侧返回轻攻击链。
- [ ] 一段攻击动画播放期间当前攻击侧保持不变。
- [ ] `AttackSide` 曲线只被每个动作消费一次，动画混合不产生误切换。

### 15.3 防御与弹反动画

- [ ] 无来袭时按下、保持和释放 Guard，依次播放 Raise、Idle/Move 和 Lower，不触发 Deflect。
- [ ] 分别注入 Light、Heavy、Thrust、Special 来袭，在有效期内按下 Guard，播放各自配置的 Deflect Type。
- [ ] Guard 已经按住后再注入来袭不会自动触发 Deflect；释放并重新按下后才可触发。
- [ ] 同一 `ContextSerial` 多次回调只播放一次 Deflect。
- [ ] Type 01～03 连续成功弹反按 Stage 01、02、03 推进；超时后重置到 Stage 01。
- [ ] Type 04 始终播放 Stage 01，不访问不存在的 Stage 02/03。
- [ ] 弹反中释放 Guard 不打断当前动画；结束后回 Neutral，仍按住则进入 Guarding。
- [ ] Deflect 与攻击续段同帧时 Deflect 优先，并清除未执行续段输入。

### 15.4 稳定性

- [ ] 动画自然结束、主动取消和 Deflect 后均无残留候选、旧动作回调或旧来袭上下文。
- [ ] 已中断动作的曲线和输入不会影响后续动作。
- [ ] 低帧率下不漏掉攻击侧提交和窗口输入。
- [ ] 缺失必需曲线时拒绝开启对应能力并输出明确日志，不静默使用硬编码时间。
