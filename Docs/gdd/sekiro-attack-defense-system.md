# 角色攻击防御系统需求

> **状态**：草案
> **创建日期**：2026-07-22
> **适用范围**：玩家角色与具备相同战斗接口的敌方角色
> **技术设计**：[角色攻击防御系统技术设计](../design/sekiro-attack-defense-system.md)

## 一、背景

项目已经具备以下战斗基础：

- `AnimAssets.lua` 已登记轻攻击、左右重攻击、地面连段、空中攻击、防御移动、格挡反馈和多组弹反动画。
- `SKInputManager` 已采集攻击按下、攻击长按时长、防御保持和动作输入缓冲。
- `ASKWeapon` 已具备攻击碰撞开关和单次攻击命中去重能力。
- `ABP_Sekiro.lua` 已支持 Root Motion、移动状态机和上半身武器 Slot。

当前缺少统一的战斗动作状态机、动画曲线消费者、左右攻击侧管理、轻重攻击分流，以及格挡和弹反对攻击动作的反馈闭环。本需求定义第一版角色攻击防御系统的稳定玩法契约。

## 二、目标

1. 使用已有动画资产完成从轻攻击、重攻击、防御到弹反的核心战斗闭环。
2. 轻攻击按照固定动作链推进，所有续段均由动画窗口和有效输入共同决定。
3. 重攻击由攻击键长按触发，具有左右侧，并可在自己的输入窗口内继续重攻击或转回轻攻击连段。
4. 攻击左右侧由动画曲线提交，运行时保留当前攻击侧和下一攻击侧两个独立状态。
5. 轻攻击与重攻击均可被目标成功格挡或弹反打断。
6. C++ 只提供通用战斗、动画采样和碰撞接口，Lua 负责具体动作编排和玩法裁决。

## 三、范围

### 3.1 本期范围

- 地面轻攻击五段链。
- 左右重攻击及重攻击连续衔接。
- 重攻击转回轻攻击链。
- 动画曲线驱动的攻击侧切换、攻击盒和输入窗口。
- 攻击输入的短按、长按和窗口内有效性判定。
- 主动防御、持续格挡和精确弹反。
- 格挡、弹反、受击或主动取消导致的攻击中断和状态清理。
- HP、架势和基础硬直结果。
- 玩家与敌方角色共用的命中裁决接口。

### 3.2 后续范围

- 空中三连与落地攻击衔接。
- 危字攻击、识破、踩踏和投技。
- 忍杀、死亡与回生演出。
- 战技、义手忍具和道具取消链。
- 网络同步。

## 四、术语

| 术语 | 定义 |
| --- | --- |
| 轻攻击 | 攻击键在长按阈值前释放，或当前动作不允许重攻击时产生的普通攻击意图。 |
| 重攻击 | 攻击键持续按住达到配置阈值后产生的攻击意图。 |
| 当前攻击侧 | 当前正在执行并用于命中、格挡和弹反方向判断的 Left/Right；一段攻击期间保持不变。 |
| 下一攻击侧 | 当前动画通过 `AttackSide` 曲线提交、供下一段攻击选择使用的 Left/Right。 |
| 连段窗口 | 动画允许接收下一次轻攻击的时间区间。 |
| 重攻击窗口 | 动画允许接收长按重攻击的时间区间。 |
| 取消窗口 | 当前攻击允许主动转入防御或闪避的时间区间。 |
| 有效输入 | 按下起点位于对应动画窗口内，尚未消费、未过期且未被更高优先级动作清除的输入。 |
| 动作序列号 | 每次开始攻击时生成的唯一运行时编号，用于拒绝已经中断动作的迟到曲线和输入。 |

## 五、动画资产基线

| 玩法语义 | 动画资产 |
| --- | --- |
| 第一段右侧轻攻击 | `AnimAssets.Attack.Right` |
| 第二段左侧轻攻击 | `AnimAssets.Attack.Left` |
| 后续轻攻击 | `AnimAssets.Attack.Combo_01`、`Combo_02`、`Combo_03` |
| 右侧重攻击 | `AnimAssets.Attack.Charged_Thrust_Right` |
| 左侧重攻击 | `AnimAssets.Attack.Charged_Thrust_Left` |
| 防御起手/循环/结束 | `AnimAssets.Guard.Raise`、`Idle`、`Move_*`、`Lower` |
| 轻格挡反馈 | `AnimAssets.Guard.Shake` |
| 中/重格挡反馈 | `AnimAssets.Guard.Interrupted`、`Interrupted_Heavy` |
| 弹反反馈 | `AnimAssets.Deflect.Type_*_Stage_*` |

`Combo_01~03` 的实际挥刀侧必须通过动画检查确认，并写入对应动画的 `AttackSide` 曲线。不得仅根据资产名称推测其左右侧。

## 六、轻攻击需求

### 6.1 固定连段

轻攻击动作链固定为：

```text
Right -> Left -> Combo_01 -> Combo_02 -> Combo_03 -> End
```

### 6.2 续段规则

- **REQ-ATK-001**：一次全新的轻攻击链必须从 `Right` 开始。
- **REQ-ATK-002**：只有 `CanAcceptLightAttack > 0` 时产生的有效轻攻击输入才能推进下一段。
- **REQ-ATK-003**：一个窗口最多消费一个轻攻击输入，多次按键不得跳过中间攻击。
- **REQ-ATK-004**：续段输入只能推进一段，进入新动作后必须重新等待该动作自己的窗口。
- **REQ-ATK-005**：窗口关闭且没有有效续段输入时，当前动画允许自然收招，本轮连段结束。
- **REQ-ATK-006**：连段结束后的下一次轻攻击重新从 `Right` 开始，不从上次中断位置恢复。
- **REQ-ATK-007**：`Combo_03` 不允许继续轻攻击，播放完成后强制结束连段。

## 七、重攻击需求

### 7.1 输入识别

- **REQ-HVY-001**：重攻击与轻攻击共用攻击键。
- **REQ-HVY-002**：攻击键按住达到 `HeavyHoldThreshold` 后才生成重攻击意图，默认阈值为 `0.30s`。
- **REQ-HVY-003**：攻击按下起点必须位于 `CanAcceptHeavyAttack > 0` 的窗口内，才有资格升级为重攻击。
- **REQ-HVY-004**：在达到阈值前释放时，若按下起点同时位于轻攻击窗口，则生成轻攻击意图。
- **REQ-HVY-005**：同一按键候选一旦升级为重攻击，必须覆盖尚未执行的轻攻击候选。

### 7.2 可用动作

- **REQ-HVY-006**：`Right`、`Left`、`Charged_Thrust_Right` 和 `Charged_Thrust_Left` 均允许配置重攻击窗口。
- **REQ-HVY-007**：`Combo_01~03` 不允许转入重攻击；其 `CanAcceptHeavyAttack` 必须为零。
- **REQ-HVY-008**：在不允许重攻击的 Combo 动作中，攻击键长按不得阻塞合法的轻攻击续段。
- **REQ-HVY-009**：Neutral 状态直接长按攻击时，首个重攻击侧由 `InitialHeavySide` 配置，默认使用 Right。

### 7.3 左右侧衔接

重攻击和轻攻击共享下一攻击侧。默认衔接如下：

| 当前攻击 | 下一攻击侧 | 轻攻击输入 | 重攻击输入 |
| --- | --- | --- | --- |
| `Right` | Left | `Left` | `Charged_Thrust_Left` |
| `Left` | Right | `Combo_01` | `Charged_Thrust_Right` |
| `Charged_Thrust_Right` | Left | `Left` | `Charged_Thrust_Left` |
| `Charged_Thrust_Left` | Right | `Combo_01` | `Charged_Thrust_Right` |

- **REQ-HVY-010**：连续重攻击必须按动画曲线提交的左右侧交替选择资源。
- **REQ-HVY-011**：重攻击后的轻攻击必须根据下一攻击侧返回轻攻击链，而不是无条件从 `Right` 重启。
- **REQ-HVY-012**：没有有效后续输入时，重攻击自然结束并终止当前攻击链。

## 八、攻击侧曲线需求

### 8.1 曲线语义

`AttackSide` 使用整数语义和阶梯插值：

| 值 | 语义 |
| --- | --- |
| `-1` | 下一攻击侧提交为 Left。 |
| `0` | 保持当前值，不提交切换。 |
| `1` | 下一攻击侧提交为 Right。 |

- **REQ-SIDE-001**：`AttackSide` 表达下一攻击侧，不得直接覆盖当前攻击侧。
- **REQ-SIDE-002**：当前攻击侧在动作开始时提交，在该动作全部攻击盒关闭前保持不变。
- **REQ-SIDE-003**：`AttackSide` 非零区间必须位于当前动作最后一个攻击盒关闭之后。
- **REQ-SIDE-004**：`AttackSide` 必须不晚于对应轻攻击或重攻击输入窗口开始帧提交。
- **REQ-SIDE-005**：有效输入产生时必须快照下一攻击侧；后续曲线变化不得修改已经接受的输入候选。
- **REQ-SIDE-006**：动画混合产生的中间值不得触发侧向切换；运行时必须使用阈值和每动作一次性消费保护。
- **REQ-SIDE-007**：当前动作被中断后，不得继续消费该动作剩余的 `AttackSide` 曲线。

### 8.2 标准时间顺序

```text
动作启动
-> 当前侧攻击盒开启
-> 命中阶段
-> 当前侧攻击盒关闭
-> AttackSide 提交下一侧
-> 轻/重攻击输入窗口
-> 收招或进入下一动作
```

## 九、窗口和输入需求

### 9.1 必需曲线

| 曲线 | 类型 | 作用 |
| --- | --- | --- |
| `AttackHitbox` | int enum | 攻击判定类型和生命周期。 |
| `AttackSide` | int enum | 提交下一攻击侧。 |
| `CanAcceptLightAttack` | int bool | 接受轻攻击续段。 |
| `CanAcceptHeavyAttack` | int bool | 接受长按重攻击。 |
| `CanCancelToGuard` | int bool | 允许攻击方主动切入防御。 |
| `CanCancelToDodge` | int bool | 允许攻击方主动切入闪避。 |

- **REQ-WIN-001**：各窗口必须由动画曲线提供，不得使用统一的 `0.5s` 连段超时替代。
- **REQ-WIN-002**：输入按下起点在窗口外时无效，即使长按阈值在窗口内达到也不得触发。
- **REQ-WIN-003**：窗口内开始的长按候选可以在窗口关闭后完成轻重分类，但不得晚于当前动作结束。
- **REQ-WIN-004**：窗口关闭后产生的新输入不得补入已经关闭的窗口。
- **REQ-WIN-005**：动作被中断时必须清除该动作接受的所有未执行候选。

## 十、防御与弹反需求

### 10.1 主动防御

- **REQ-DEF-001**：Neutral 状态按下防御必须立即建立机械防御状态，并播放 `Guard.Raise`。
- **REQ-DEF-002**：持续按住防御进入 `Guard.Idle` 或四向 `Guard.Move_*`。
- **REQ-DEF-003**：释放防御播放 `Guard.Lower`，结束机械防御状态。
- **REQ-DEF-004**：攻击方主动从轻攻击或重攻击切入防御时，必须满足当前动画的 `CanCancelToGuard`。

### 10.2 命中裁决

命中目标时按以下顺序裁决：

```text
无敌
> 不可防御/防御方向无效
> 弹反
> 格挡
> 普通命中
```

- **REQ-DEF-005**：防御键新按下距命中不超过 `DeflectWindow`、攻击可弹反且位于有效防御扇区时，结果为 Deflect。
- **REQ-DEF-006**：超过弹反窗口但仍持续防御、攻击可格挡且位于有效防御扇区时，结果为 Block。
- **REQ-DEF-007**：轻攻击和重攻击默认均可格挡、可弹反。
- **REQ-DEF-008**：目标成功 Block 或 Deflect 都必须立即打断攻击方当前攻击。
- **REQ-DEF-009**：Deflect 对攻击方施加更高架势伤害和更长硬直；Block 施加较短武器回弹。
- **REQ-DEF-010**：Block 和 Deflect 必须在同一帧关闭攻击盒、清除续段输入并使当前动作序列号失效。
- **REQ-DEF-011**：防御结果需要携带当前攻击侧，供左右格挡、弹反和回弹表现选择使用。

## 十一、HP 与架势需求

- **REQ-VIT-001**：普通命中造成 HP 伤害和目标架势伤害。
- **REQ-VIT-002**：格挡默认不造成 HP 伤害，但增加防御方架势。
- **REQ-VIT-003**：弹反默认不造成防御方 HP 伤害，并增加攻击方架势。
- **REQ-VIT-004**：架势达到上限时进入 PostureBroken，优先级高于普通动作。
- **REQ-VIT-005**：架势只在未受击、未防御并经过恢复延迟后恢复。
- **REQ-VIT-006**：所有伤害、架势和恢复参数必须来自配置，不得在武器 Actor 中硬编码。

## 十二、优先级与中断

动作优先级从高到低为：

```text
死亡/演出锁定
> 架势崩坏
> 普通受击
> 弹反/格挡反馈
> 主动防御
> 闪避
> 重攻击续段
> 轻攻击续段
> 自然收招
```

- **REQ-INT-001**：高优先级动作可以中断低优先级动作，但仍需遵守明确配置的不可中断状态。
- **REQ-INT-002**：由目标 Block/Deflect 返回的攻击中断不受攻击方主动取消窗口限制。
- **REQ-INT-003**：主动 Guard/Dodge 取消必须服从对应动画曲线。
- **REQ-INT-004**：任何攻击中断都必须关闭攻击盒、清理输入候选和停止消费旧动作曲线。
- **REQ-INT-005**：中断后本轮轻攻击链结束；下一次全新轻攻击从 `Right` 开始。

## 十三、边界情况

| 场景 | 预期结果 |
| --- | --- |
| 同一窗口多次按攻击 | 合并为一次续段，不跳段。 |
| 轻攻击候选随后达到长按阈值 | 当前节点允许重攻击时升级为 Heavy，否则保持 Light。 |
| 窗口内按下、窗口外释放 | 使用按下时快照继续分类，动作结束前有效。 |
| Hitbox 尚未关闭时出现 AttackSide 值 | 忽略并输出开发期错误。 |
| 曲线混合值为 `0.5` | 不提交侧向，等待稳定达到阈值。 |
| 动作切换后收到旧输入回调 | 通过动作序列号拒绝。 |
| Block/Deflect 与续段同帧发生 | Block/Deflect 优先，续段作废。 |
| 目标在攻击中死亡或失效 | 关闭攻击盒，当前动作允许收招，不再产生新命中。 |
| 重攻击连续输入终止 | 当前重攻击收招，攻击链结束。 |
| Combo 中长按攻击 | 不产生重攻击，可按轻攻击窗口继续 Combo。 |

## 十四、非功能需求

- **REQ-NFR-001**：战斗判定在游戏线程执行，不得在动画工作线程修改 Actor、组件或 Lua 状态。
- **REQ-NFR-002**：同一攻击对同一目标最多结算一次。
- **REQ-NFR-003**：攻击窗口在 30fps 和 60fps 下必须产生一致结果。
- **REQ-NFR-004**：动画淡入淡出不得造成旧动作曲线被新动作重复消费。
- **REQ-NFR-005**：C++ 不硬编码 `/Game` 动画路径、具体连段名称或角色专属数值。
- **REQ-NFR-006**：所有状态转换应提供可开关的调试日志，日志至少包含动作 ID、序列号、当前侧、下一侧、输入类型和中断原因。

## 十五、验收标准

### 15.1 轻攻击

- [ ] 连续在各自动画窗口内短按攻击，正确播放 `Right -> Left -> Combo_01 -> Combo_02 -> Combo_03`。
- [ ] 任意一段没有有效续段输入时自然结束，下一次攻击从 `Right` 开始。
- [ ] 同一窗口连按不会跳过攻击段。
- [ ] Combo 阶段长按不会触发重攻击，也不会阻塞合法轻攻击续段。

### 15.2 重攻击与侧向

- [ ] `Right` 的有效重攻击输入进入 `Charged_Thrust_Left`。
- [ ] `Left` 的有效重攻击输入进入 `Charged_Thrust_Right`。
- [ ] 连续重攻击按 `Right/Left` 交替播放。
- [ ] 重攻击窗口内短按可按当前下一攻击侧返回轻攻击链。
- [ ] Hitbox 激活期间当前攻击侧保持不变。
- [ ] `AttackSide` 曲线只被每个动作消费一次，动画混合不产生误切换。

### 15.3 防御与中断

- [ ] 轻攻击命中持续防御目标时产生 Block，并打断攻击方。
- [ ] 重攻击命中持续防御目标时产生 Block，并打断攻击方。
- [ ] 轻攻击在弹反窗口命中时产生 Deflect，并打断攻击方。
- [ ] 重攻击在弹反窗口命中时产生 Deflect，并打断攻击方。
- [ ] Block/Deflect 同帧清除攻击盒和所有未执行续段输入。
- [ ] 左右攻击侧正确传入防御结果，反馈动画方向与攻击侧一致。

### 15.4 稳定性

- [ ] 动画自然结束、主动取消、受击、Block 和 Deflect 后均无残留攻击盒。
- [ ] 已中断动作的曲线和输入不会影响后续动作。
- [ ] 低帧率下不漏掉攻击侧提交和窗口输入。
- [ ] 缺失必需曲线时拒绝开启对应能力并输出明确日志，不静默使用硬编码时间。

## 十六、待资产核验项

1. `Combo_01~03` 各自的当前攻击侧和下一攻击侧。
2. `Right/Left` 与两条重攻击的精确 Hitbox、AttackSide 和输入窗口帧。
3. `Guard.Interrupted`、`Interrupted_Heavy` 是否适合作为攻击方 Block/Deflect 回弹占位。
4. 当前攻击资源的 Root Motion 是否能在全身战斗 Slot 中正确提取。
5. 普通受击、攻击方被弹开和专用架势崩坏动画是否需要从未登记资产中补充。
